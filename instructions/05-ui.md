# 05. UI

Goal: a map tool that looks like a real product and makes the decision model visible and tunable.

## Design system (follow everywhere)
**Feel:** clean civic-tech decision tool. Neutral UI, one green accent, the map is the hero.

| Token | Value |
|---|---|
| Font | Geist (create-next-app default). Numbers use `tabular-nums`. Score math uses `font-mono text-xs`. |
| Neutrals | Tailwind `zinc`. Text `zinc-900`, secondary `zinc-500`, borders `zinc-200`. |
| Accent | `emerald-700` for logo, links, focus, slider fill. |
| Score scale | `#ffffcc` (0) → `#78c679` (50) → `#006837` (100) |
| Compare colors | Spot A `indigo-600`, Spot B `amber-500` (outlines, letters, column headers only) |
| Surfaces | `bg-white/95 backdrop-blur-sm border border-zinc-200 shadow-lg rounded-2xl` |
| Spacing | Panel `p-5`, gaps `gap-4`, rows `py-2.5` |
| Section labels | `text-xs font-medium uppercase tracking-wide text-zinc-500` |
| Motion | 150 to 250 ms. Panels `animate-in fade-in slide-in-from-right-4`. Fly-to 800 ms. Hex color transitions 300 ms. |
| Theme | Light only. |

**Never:** emoji, gradients on UI chrome, extra accent colors, spinners where a skeleton fits, scores described as a "chance of success."

## 5.1 Colors, badges, icon
`lib/colors.ts`:
```ts
type RGB = [number, number, number];

const STOPS: [number, RGB][] = [
  [0, [255, 255, 204]],
  [50, [120, 198, 121]],
  [100, [0, 104, 55]],
];

export function scoreToRgb(score: number): RGB {
  const s = Math.max(0, Math.min(100, score));
  const i = s <= 50 ? 0 : 1;
  const [s0, c0] = STOPS[i];
  const [s1, c1] = STOPS[i + 1];
  const t = (s - s0) / (s1 - s0);
  return c0.map((v, k) => Math.round(v + (c1[k] - v) * t)) as RGB;
}

export const scoreToColor = (score: number, alpha = 255): [number, number, number, number] => [...scoreToRgb(score), alpha];
export const scoreToCss = (score: number) => `rgb(${scoreToRgb(score).join(" ")})`;
export const scoreTextColor = (score: number) => (score >= 55 ? "#ffffff" : "#18181b");

export const SPOT_COLORS = { A: [79, 70, 229] as RGB, B: [245, 158, 11] as RGB };
```
`components/panel/ScoreBadge.tsx`: rounded square with the score, sizes `sm` (28px) and `lg` (56px).
`app/icon.svg`: emerald-700 hexagon. Metadata title "Site Scout", description "A location decision model for small businesses."

## 5.2 Hooks + URL state
- `useHexFeatures(type)` → `{ data: HexFeatures[], loading, error, retry }`.
- `useHexDetail(h3, type)` → `HexDetailResponse | null`, `error = "not_found"` on 404.
- `useVerdict(h3, type, weights)` → POST, **debounced 500 ms** on weight changes, ignores stale responses.
- `useCompare(a, b, type, weights)` → same pattern.
- `usePlan()` → `{ run(text), data: PlanResponse | null, loading, error }` (see 5.4b).
- All use `fetch` + `AbortController`.

`lib/urlState.ts`: read and write `?type=boba&w=<modelKey>&hex=<h3>&a=<h3>&b=<h3>`. Use `parseModelKey` for `w`. Omit `w` when weights are the defaults.

In `SiteScout.tsx`:
```ts
const scored = useMemo(() => scoreAll(features ?? [], weights), [features, weights]);
const byH3 = useMemo(() => new Map(scored.map((h) => [h.h3, h])), [scored]);
```
Changing type resets weights to `DEFAULT_WEIGHTS[type]` and clears selection and compare.

## 5.3 Map + shell
`components/map/HexMap.tsx` (`"use client"`). Props: `hexes: ScoredHex[]`, `selectedH3`, `compareA`, `compareB`, `labels`, `competitors`, `onSelect(h3 | null)`, `viewState`, `onViewStateChange`.
```tsx
import DeckGL from "@deck.gl/react";
import { H3HexagonLayer } from "@deck.gl/geo-layers";
import { ScatterplotLayer, TextLayer } from "@deck.gl/layers";
import Map from "react-map-gl/maplibre";
import "maplibre-gl/dist/maplibre-gl.css";

const MAP_STYLE = "https://basemaps.cartocdn.com/gl/positron-gl-style/style.json";

const focus = [selectedH3, compareA, compareB].filter(Boolean) as string[];
const outline = (h3: string): [number, number, number, number] =>
  h3 === compareA ? [...SPOT_COLORS.A, 255] :
  h3 === compareB ? [...SPOT_COLORS.B, 255] :
  h3 === selectedH3 ? [24, 24, 27, 255] : [255, 255, 255, 160];

const hexLayer = new H3HexagonLayer<ScoredHex>({
  id: "hexes",
  data: hexes,
  pickable: true,
  autoHighlight: true,
  highlightColor: [255, 255, 255, 70],
  extruded: false,
  stroked: true,
  getHexagon: (d) => d.h3,
  getFillColor: (d) => scoreToColor(d.score, focus.length ? (focus.includes(d.h3) ? 235 : 90) : 160),
  getLineColor: (d) => outline(d.h3),
  getLineWidth: (d) => (focus.includes(d.h3) ? 3 : 1),
  lineWidthUnits: "pixels",
  transitions: { getFillColor: 300 },
  updateTriggers: { getFillColor: [focus.join()], getLineColor: [focus.join()], getLineWidth: [focus.join()] },
  onClick: (info) => info.object && onSelect(info.object.h3),
});

// labels: { text: "A" | "B"; lat: number; lng: number }[], built in SiteScout from byH3
const labelLayer = new TextLayer({
  id: "compare-labels",
  data: labels,
  getPosition: (d) => [d.lng, d.lat],
  getText: (d) => d.text,
  getSize: 18,
  getColor: [255, 255, 255, 255],
  fontWeight: 700,
  outlineWidth: 3,
  outlineColor: [24, 24, 27, 255],
  fontSettings: { sdf: true },
});

const competitorLayer = new ScatterplotLayer<Competitor>({
  id: "competitors",
  data: competitors,
  pickable: true,
  getPosition: (d) => [d.lng, d.lat],
  getRadius: 6,
  radiusUnits: "pixels",
  getFillColor: [225, 29, 72, 255],
  stroked: true,
  getLineColor: [255, 255, 255, 255],
  lineWidthUnits: "pixels",
  getLineWidth: 2,
});
```
- `DeckGL` with `controller={{ dragRotate: false }}`, layers `[hexLayer, competitorLayer, labelLayer]`, `<Map mapStyle={MAP_STYLE} />` as child.
- Tooltip: hex → `Score 82 · Strong · #4 of 142`; competitor → name. White card styling.
- Click on empty map → `onSelect(null)`.

`components/SiteScout.tsx` (`"use client"`): holds `type`, `weights`, `selectedH3`, `compareA`, `compareB`, `pickingB` (bool), `viewState` (`{ latitude: 34.06, longitude: -117.79, zoom: 11.6, pitch: 0, bearing: 0 }`). Map loaded with `dynamic(() => import("./map/HexMap"), { ssr: false })`. Full screen `h-dvh w-full relative`.

`app/page.tsx`: `<Suspense><SiteScout /></Suspense>`.

`ControlPanel.tsx`, top to bottom:
1. Brand: emerald hexagon + "Site Scout" (`text-lg font-semibold`). Tagline: "A decision model for where to open your business."
2. `IntentBox` (5.4b).
3. `TypeSelect`: 5 toggle chips (icon + `short`). Selected `bg-zinc-900 text-white`, others `bg-zinc-100 hover:bg-zinc-200`.
4. `PriorityControls` (5.4).
5. Summary: "142 areas scored · 12 strong spots".
6. `TopSpots` (5.6).
7. Footer: "How the model works" `Popover` + credit "Data: Overture Maps · LLM: Llama 3.3 70B".

Popover text:
> Every hexagon (about 0.7 sq km) gets a demand number: each nearby college, office, apartment or store counts, multiplied by how much you said it matters. That demand is divided by the competition penalty. Scores compare areas to each other: 90 means better than 90% of nearby areas. The model makes every decision. The AI only explains it.

`Legend.tsx`: gradient bar, "Weak · Decent · Strong", caption "Compared to nearby areas under your priorities."

**Done when:** mock hexes render, chips switch types, hover and click work.

## 5.4 Priority sliders: `PriorityControls.tsx`
This is the decision model on screen. Make it feel responsive.
- Section label "Your priorities".
- One row per `DRIVER_GROUPS` entry plus "Avoid competition". Each row: label + small hint under it (`text-[11px] text-zinc-500`), shadcn `Slider` (`min 0`, `max 3`, `step 0.5`), and the word from `weightWord` on the right (`ignored / low / medium / high`).
- Update weights on every slider move. The map rescores live because `scoreAll` runs in `useMemo`.
- "Reset to {type} defaults" text button, shown only when `!isDefault(weights, type)`.
- When weights differ from defaults, show a small `Badge variant="secondary"`: "Custom model".

**Done when:** dragging "Students" to 0 visibly recolors the map and reorders Top spots instantly.

## 5.4b Plain-English input: `IntentBox.tsx`
Sits in ControlPanel right under the tagline, above the type chips. It's the first thing a judge sees.
- Section label "Describe your business".
- shadcn `Textarea` (add with `npx shadcn@latest add textarea`), 2 rows, placeholder: "Boba shop near students. I really want to avoid competition."
- Primary button "Find my spot" (emerald-700, full width). Enter submits, Shift+Enter adds a new line.
- Under the box, 3 example chips that fill and submit on click:
  - "Boba shop near college students, avoid competition"
  - "Laundromat for apartment renters"
  - "Gym for office workers and residents"
- While loading: button shows "Thinking…" and is disabled. Skeleton line where the summary goes.
- On success:
  1. Set `type` and `weights` from the response. The sliders animate to the new values (shadcn Slider animates if the value changes in one render).
  2. Clear the selection and compare, and fly back to the default view.
  3. Show the `summary` in a small card: emerald left border, `text-sm`, with a caption under it: "Llama set these priorities. The model picks the spots." If `fromLLM` is false, the caption says "Matched by keyword. Adjust the sliders below."
- Error: inline "Couldn't read that. Try one of the examples."

Wire it in `SiteScout` with a `usePlan()` hook (POST, AbortController, returns `{ run(text), data, loading, error }`).

**Done when:** clicking the laundromat example switches the type, moves the sliders, shows the summary and recolors the map.

## 5.5 Hex panel: `HexPanel.tsx`
Top to bottom:
1. **Header:** `ScoreBadge lg`, "Strong spot" (`text-xl font-semibold`), "Rank #4 of 142 for a {label}". Close X (`aria-label="Close"`).
2. **VerdictCard:** label "AI explanation" + `Badge variant="secondary"` "Llama 3.3 70B". 3-line skeleton while loading, fade in after. Refetches (debounced) when weights change.
3. **ScoreBreakdown:** section label "Why this score". Lines from `explainScore()` in `font-mono text-xs bg-zinc-50 rounded-lg p-3`. Under it, a stacked horizontal bar showing how much each group contributes to demand (`weight × count`), with a tiny legend. This is the most important part for judges.
4. **Demand sources:** rows from `driverBreakdown`: `prettyCategory`, group tag (`text-[11px] text-zinc-500`), count, thin emerald bar scaled to the max.
5. **Nearest competitors:** rose dot, name, `prettyCategory · formatDistance`.
6. **Actions:** primary button "Compare with another spot" (sets `compareA` = this hex, `pickingB = true`), secondary button "Download report" (opens `/report?type=&w=&hex=` in a new tab, lucide `FileText`), link "Open in Google Maps" with lucide `ExternalLink` (`https://www.google.com/maps/search/?api=1&query={lat},{lng}`).

States: skeletons while loading, "No data for this area" on 404, "No competitors nearby. That's a good sign." when empty.

Pass `detail.nearestCompetitors` to the map so rose dots appear.

## 5.6 Top spots + fly-to
`TopSpots.tsx`: "Top spots", first 3 of `scored`. Each row: rank, `ScoreBadge sm`, "Strong spot", subline with the top contributing group ("Mostly students · 0 competitors"). Selected row `bg-zinc-100`. When weights change, rows reorder with a short fade.

## 5.7 Compare: `ComparePanel.tsx`
Flow:
1. "Compare with another spot" in HexPanel → `compareA` set, `pickingB = true`, a pill appears top-center: "Click a second spot to compare with A" + Cancel.
2. Next hex click while `pickingB` → `compareB` set, right panel switches to ComparePanel, map fits both hexes.
3. Top spots rows also get a small "Compare" icon button that fills A then B.

Panel, top to bottom:
1. Header "A vs B" with colored letters, Swap button, Close button.
2. **Model decision:** big row "Model picks Spot A" with the winner's letter in its color, plus "Score 91 vs 64 under your priorities."
3. **AI explanation:** label "Why" + "Llama 3.3 70B" badge, 3-line skeleton, then the text.
4. **Side-by-side table:** rows Score, Rank, Students, Workers, Residents, Shoppers, Competitors, Demand. Columns A and B. Bold the better value in each row (fewer is better for Competitors).
5. Footer: "Change priorities on the left and the decision updates."

Changing weights recomputes the winner instantly (client side, `pickWinner`) and refetches the explanation (debounced).

**Done when:** comparing two spots shows a winner, a table, and an explanation, and moving a slider can flip the winner.

## 5.9 Place search: `PlaceSearch.tsx`
Floating search bar, `absolute top-4 left-1/2 -translate-x-1/2 w-[360px]`, same surface style.
- shadcn `Command` inside a `Popover`: input placeholder "Search a place, like Cal Poly or Target".
- Debounce 250 ms, call `/api/search?q=`. Show up to 8 results: name (`font-medium`), `prettyCategory` under it.
- Pick a result: fly to it (zoom 14), and if its `h3` exists in the current scored hexes, select it. If not, show a toast: "No data for that exact spot. Showing the area around it."
- `Cmd+K` focuses the search. Empty state "No places found." Hide the bar while picking B in compare.

## 5.10 Owner report: `app/report/page.tsx`
A printable one-pager an owner can bring to a landlord, lender or the SBA. Client component reading `type`, `w`, `hex` from the URL.
- Fetches `/api/hexes`, `/api/hex/[id]` and `/api/verdict` (same weights).
- White page, max width 720px, `p-10`, print-friendly. Sections:
  1. Header: "Site Scout location report", business label, date, small emerald hexagon.
  2. Score: `ScoreBadge lg` + label + "Rank #4 of 142 nearby areas".
  3. "Owner priorities": the 5 weights as words (`weightWord`).
  4. "Why this score": `explainScore()` lines.
  5. "AI summary": the verdict, with "Explanation by Llama 3.3 70B. Decision by the Site Scout model."
  6. "Demand sources" and "Nearest competitors" tables.
  7. Static map: a small image of the area is optional. A link "View on map" back to the app URL is enough.
  8. Footer: data sources (Overture Maps, Snowflake), "Scores compare areas to each other and are not a guarantee of success."
- Buttons at top: "Print or save as PDF" (`window.print()`) and "Back to map". Hide both with `print:hidden`.
- Loading skeleton and a clear error state ("Couldn't build this report. Go back and try again.").

## 5.11 Error boundary + status
- `app/error.tsx`: friendly card "Something went wrong" with "Try again" (`reset()`) and "Reload" buttons. Log the error to the console.
- `components/StatusBadge.tsx`: small pill at bottom-right above the attribution. Green dot "Live data" when `source === "live"`, amber "Offline data" for `offline`, zinc "Demo data" for `mock`. Tooltip explains each.
- Toasts with `sonner` (`<Toaster />` in layout): show for 429 ("Slow down a little, try again in a minute"), for network errors on plan/verdict/compare, and when copying a share link.
- "Share" button in ControlPanel footer copies the current URL and toasts "Link copied".
